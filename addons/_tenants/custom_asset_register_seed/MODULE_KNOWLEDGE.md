# custom_asset_register_seed

Per-unit fixed-asset **subledger (register)** for PT Aero Inovasi Media (the tenant)'s
drone fleet, reconciled to the 31-May-2026 opening-balance GL. Tenant-scoped —
install only on the tenant databases (`trn_tenant_begbal`, then `prd_tenant`).

## Why this exists

The drones are **already** carried as a lump sum in the tenant opening balance
(`custom_opening_balance_seed`):

| GL account | | amount |
|---|---|---:|
| `1205104000` | Fixed Assets-Cost-Office & outlet equipment | Dr 27,110,131,391 |
| `1205203000` | Accum depre-Office & outlet equipment | Cr 6,776,493,895 |
| | **net book value** | **20,333,637,496** |

This module builds the **asset register that ties out to that GL** — it does **not**
post an acquisition journal. `custom.fixed.asset.create()` touches no GL; only
depreciation posts, and this module posts none at install (see below).

## How the begbal depreciation is modelled

The base model has no "opening accumulated depreciation" field. We use the fact
that a `custom.fixed.asset.depreciation.line` with `posted=True, move_id=False`
counts into `accumulated_depreciation` / `net_book_value` but is **never posted to
the GL** and **never re-posted** by `_cron_post_due_depreciation` (which filters
`not posted`).

The GL accum (6,776,493,895) is **exactly 25% of cost** → **12 months of a 48-month
life** were depreciated by the opening date. So the loader (`hooks.post_init_hook`):

1. creates each asset at PO unit cost, `useful_life_months=48`,
   `depreciation_method=straight_line`, `depreciation_date_mode=specific`,
   `posting_date=DEP_START` (2025-06-30, chosen so the 12 elapsed lines end on the
   opening date);
2. `action_confirm()` → builds the 48-month schedule;
3. marks every line **dated ≤ 31-May-2026** as `posted=True` (the 12 history
   lines). The remaining **36 forward lines are all dated ≥ Jun-2026**, so the
   monthly cron depreciates strictly forward and never touches history or the GL.

Zero-value listing-only units get `depreciation_method=none` (nothing to depreciate).

### Reconciliation (consistent-rate)

Register booked at PO cost; accum applied at the same 25% rate as the GL. All three
variances trace to the single **+34,976,845** PO-vs-GL cost gap:

| | register | GL | variance |
|---|---:|---:|---:|
| cost | 27,145,108,236 | 27,110,131,391 | +34,976,845 |
| accum depreciation | 6,786,277,059 | 6,776,493,895 | +9,783,164 (25%) |
| net book value | 20,358,831,177 | 20,333,637,496 | +25,193,681 (75%) |

Verify with `scripts/tenants/tenant/verify_asset_register.py`. The GL is **not**
adjusted — the variance is surfaced for Finance.

## Idempotency

- `data/seed_functions.xml` re-runs `_seed_aim_asset_register` on every `-u`
  (upsert group + location, non-destructive).
- `post_init_hook` **skips the whole register load** if any the tenant
  `custom.fixed.asset` already exists → safe to re-run / upgrade.
- Company resolved by NAME → portable across the clone/prod databases.
